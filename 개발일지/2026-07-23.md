# 개발 일지 — 관리자 문서 관리 기능 신규 개발

**날짜:** 2026.7.23
**대상:** llm-frontend (React + TypeScript)
**요약:** 관리자가 RAG 근거 문서를 업로드·조회·삭제하는 문서 관리 기능을 4계층(타입→서비스→훅→화면)으로 새로 만들었다. 스웨거 문서 4개 엔드포인트(+원본 다운로드)를 코드에 반영하고, MARS 페이지 스타일에 맞춰 UI를 구성했다.

---

## 1. 관리자 문서 관리 — 4계층 신설

스웨거에 새로 추가된 엔드포인트(`/api/v1/admin/documents` 업로드/목록/상태/삭제)를 기존 기능들과 같은 4계층 패턴으로 구현했다.

- **`types/adminDocument.ts`** — 업로드/목록/상태/삭제 응답 DTO. status는 서버가 문자열로 주므로 `'PROCESSING' | 'COMPLETED' | 'FAILED' | (string & {})`로 열어둠(모르는 값도 허용).
- **`api/services/adminDocument.ts`** — 엔드포인트 래퍼.
- **`hooks/useAdminDocument.ts`** — React Query 훅(목록/업로드/삭제).
- **`pages/AdminDocuments.tsx`** — 드래그앤드롭 업로드 존 + 상태 필터 + 목록 테이블.

### 배운 것 — 업로드는 `Content-Type: undefined`

multipart/form-data 업로드는 브라우저/axios가 `boundary`를 자동으로 붙여야 파싱된다. 헤더를 직접 지정하면 boundary가 빠져 서버가 못 읽는다. 그래서 **"직접 정하지 말고 비워라"**는 의미로 `Content-Type: undefined`를 넘겼다.

### 배운 것 — 인증 다운로드는 fetch→blob

`<a href>` 링크로는 Authorization 헤더를 실을 수 없다. 인증이 필요한 파일은 `fetch`로 토큰을 실어 받고, 받은 blob을 임시 URL로 만들어 가짜 링크를 클릭시키는 우회가 필요하다. 이 공용 코어(`downloadFileWithAuth`)를 `utils/downloadAttachment.ts`에 두고 채팅 첨부·RAG 원본·관리자 문서가 공유하게 했다.

## 2. AdminPage 탭 구조 도입

기존 회원 관리 화면을 **회원 관리 / 문서 관리** 탭으로 나눴다. 활성 탭에 brand 그라디언트 밑줄. 문서 관리 탭에서 `<AdminDocuments />`를 렌더.

## 3. 문서 상태 처리 — 조건부 폴링 도입

색인은 시간이 걸리는 백엔드 작업이라, 진행 상태(PROCESSING→COMPLETED)를 반영하려면 주기적으로 다시 불러와야 한다. 헬스체크(`useServerStatus`)와 같은 **조건부 폴링**으로 구현했다.

- 처리 중 문서가 하나라도 있으면 목록을 주기적으로 재요청, 전부 끝나면 폴링 정지.
- 문서별 status API를 개별 호출하지 않고 **목록 1회 호출로 전체 상태를 배치 갱신** — 요청 폭주 방지.

---

## 오늘의 회고

- 새 기능도 "타입→서비스→훅→화면" 4계층을 그대로 따르니 구조 고민 없이 빠르게 뼈대가 섰다. 기존 패턴을 지키는 것의 이득.
- 다운로드 로직을 처음부터 공용 코어로 뽑아, 세 소비처가 같은 함수를 쓰게 한 게 깔끔했다. 나중에 관리자 목록에서 다운로드 버튼을 빼도 코어는 그대로 남아 재사용된다.
