# 개발 일지 — 문서 색인 상태 정규화 & 폴링 안정화

**날짜:** 2026.7.24
**대상:** llm-frontend (React + TypeScript)
**요약:** 관리자 문서 목록에서 "완료됐는데 계속 처리 중으로 뜨는" 문제와 "완료 후에도 폴링이 안 멈추는" 문제를 잡았다. 원인은 서버가 주는 status 값(`queued`)이 코드가 기대한 대문자 문자열과 달랐던 것. status 정규화 계층을 도입해 배지·필터·폴링이 한 기준을 공유하게 했다.

---

## 증상

문서 관리 화면에서 며칠 전 올린 문서까지 **전부 "처리 중"**으로 표시됐다. 상태 필터(전체/처리중/완료/실패)를 눌러도 "조건에 맞는 문서가 없습니다"만 떴다.

## 진단 — 실제 서버 응답부터 확인

가정으로 고치지 않고, 브라우저 네트워크 탭에서 실제 목록 응답을 봤다:

```json
"status": "queued"
```

코드는 대문자 `"COMPLETED" / "PROCESSING"`을 기대하고 `===`로 비교하고 있었다. 서버는 소문자 `"queued"`를 줬다. 그래서:
- 어떤 status도 `COMPLETED`에 안 걸려 → 전부 default("처리 중")로 떨어짐
- 폴링 중단 조건(`d.status === 'PROCESSING'`)도 안 맞아 → 실제로 처리 중인지 판단이 어긋남

## 해결 — 상태 정규화 계층 (`normalizeDocStatus`)

`utils/document.ts`에 정규화 함수를 만들어, 서버가 어떤 표현을 주든 3가지(`completed`/`failed`/`processing`)로 통일했다.

```ts
if (/(complete|success|done|indexed|ready|\bok\b)/.test(s)) return 'completed'
if (/(fail|error|reject|cancel)/.test(s)) return 'failed'
return 'processing'   // queued/pending/running 등 진행 상태
```

이 함수 하나를 **배지 표시·상태 필터·폴링 중단 조건**이 전부 공유한다. 서버가 status 표현을 바꿔도 한 곳만 고치면 된다.

### 배운 것 — 외부 값은 그대로 비교하지 말고 한 겹 번역한다

대소문자·동의어·미래에 추가될 값까지, 외부(서버)가 주는 열거값을 `===`로 직접 비교하면 표현이 조금만 달라도 깨진다. **입구에서 한 번 정규화**하고 안쪽 로직은 깨끗한 값만 다루게 하니 배지·필터·폴링 세 곳의 버그가 한 번에 정리됐다.

## 곁가지로 확인한 것 — 진짜 원인은 백엔드

`queued`가 며칠째 유지된다는 건 **백엔드 색인 워커가 큐를 소비하지 않고 있다**는 뜻이다. 프론트 폴링은 정상 동작하며, 서버가 색인을 끝내 `completed`로 바꿔야 폴링이 멈춘다. 이건 프론트로는 못 고치는 부분이라 백엔드 확인 요청으로 넘겼다.

---

## 오늘의 회고

- "완료인데 처리 중" 같은 표시 버그를 만나면, UI 로직부터 의심하기 전에 **서버가 실제로 뭘 주는지(status 원본 값)**를 먼저 봤어야 했다. 실제 값 하나 확인하니 원인이 즉시 잡혔다.
- 정규화를 배지 하나에만 넣지 않고 폴링 조건까지 같은 함수로 통일한 게 좋았다. 표시와 로직이 서로 다른 기준을 쓰면 "화면은 완료인데 폴링은 계속 도는" 어긋남이 생긴다.
